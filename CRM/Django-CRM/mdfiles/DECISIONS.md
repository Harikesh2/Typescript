# DECISIONS — Django CRM Next.js Frontend

| ID | Date | Decision | Why | Status |
|----|------|----------|-----|--------|
| D-01 | 2026-08-11 | Next.js app inside repo as `/frontend` | One repo for the CRM; deploys together with backend; easy Docker/compose wiring | Active |
| D-02 | 2026-08-11 | Auth via Next.js BFF proxy + httpOnly cookie | Token never in browser JS, no CORS, DRF token auth is CSRF-exempt so the proxy is clean | Active |
| D-03 | 2026-08-11 | Keep legacy Bootstrap templates, mark deprecated | Avoid breaking existing users during migration; remove later | Active |
| D-04 | 2026-08-11 | Design: light + soft pastel gradients | User preference; modern, soft, data-friendly | Active |
| D-05 | 2026-08-11 | Dashboard v1 = stats cards only | User preference; charts deferred to v2 | Active |
| D-06 | 2026-08-11 | `/api/stats/` requires token auth | Aggregates are sensitive; it powers an authenticated dashboard | Active |
| D-07 | 2026-08-11 | Pagination opt-in via `?page=`, minimal impl | Keeps existing array-shape tests green; don't overinvest now | Active |
| D-08 | 2026-08-11 | `?state=` filter via a `get_queryset()` override (no `django-filter` dependency) | Exact match is one filter; avoids adding a third-party dependency for a single field | Active |
| D-09 | 2026-08-11 | Stats time windows: week = UTC week starting Monday; month = UTC calendar month | Simple, unambiguous semantics; consistent with `USE_TZ=True` / `TIME_ZONE=UTC` | Active |
| D-10 | 2026-08-11 | Design system: GitHub Primer (dark/night) via `@primer/react` + `@primer/primitives` + `styled-components` | Agent scaffolded Phase 1 with Primer before D-04 styling was built; Primer gives a complete, accessible component + token system out of the box | Active — supersedes D-04 |
| D-11 | 2026-08-12 | Login uses username (not email) | Matches DRF `obtain_auth_token` which expects `username` field; avoids backend changes | Active |
| D-12 | 2026-08-12 | Auth pages: Primer + subtle gradient accent (radial backdrop) | Reconciles "gradient hero" plan with D-10 adoption; keeps Primer as source of truth for components/tokens while adding a light brand touch | Active |
| D-13 | 2026-08-12 | Topbar username chip deferred to Phase 3 | Keeps Phase 2 scope tight; `/api/auth/me/` exists for future use | Active |
| D-14 | 2026-08-12 | Route protection via `proxy.ts` (not `middleware.ts`) | Next 16.3 convention; `cookies()` is async, `context.params` is a Promise, Node runtime default | Active |
| D-15 | 2026-08-12 | Logout = client-side cookie clear (no backend endpoint) | DRF tokens don't expire; session gate is cookie presence via proxy | Active |
| D-16 | 2026-08-13 | Register auto-login: reuse token from register response | Avoids extra round-trip; user lands directly in dashboard after signup | Active |
| D-17 | 2026-08-13 | BFF proxy forwards `request.body` without `duplex: 'half'` | `duplex` not in TS `RequestInit`; streaming body works via default fetch behavior in Node 18+ | Superseded by D-27 |
| D-26 | 2026-08-14 | `frontend/src/lib/auth.ts` `getDjangoApiUrl()` throws if `DJANGO_API_URL` is unset in `NODE_ENV=production` | Silent localhost fallback would break prod routing; fail fast is cheaper than a 3am page | Active |
| D-27 | 2026-08-14 | BFF proxy buffers the request body (`await request.arrayBuffer()`) for non-GET/HEAD and forwards it as `body`, plus `redirect: 'manual'` | A `ReadableStream` body passed straight into `fetch` after the request is inspected is silently dropped, so POST/PUT/PATCH/DELETE reach Django empty (400). Buffering once fixes writes (login/register/new-record/edit); `redirect: 'manual'` stops Next swallowing upstream 3xx | Active |
| D-18 | 2026-08-13 | `proxy.ts` exports `proxy` function (not `middleware`) | Next 16.3 Turbopack requires `proxy` export; `middleware` export causes build failure | Active |
| D-19 | 2026-08-13 | Records sorting is server-side via DataTable `externalSorting` + `onToggleSort` → `?ordering=` | Client-side sort only reorders the current page; wrong across pages with server pagination | Active |
| D-20 | 2026-08-13 | Records state filter is a `Select` populated from `/api/stats/` `by_state` | Token-gated but user is always authenticated on `/records`; clean single-select UX vs free-text | Active |
| D-21 | 2026-08-13 | BFF proxy preserves the client's trailing slash via `request.nextUrl.pathname` (was `params.path.join('/')`) | DRF routes require `/`; without it Django's `APPEND_SLASH` 301-redirects and `fetch` converts POST/PATCH/DELETE to GET, silently breaking Phase 4 writes | Active |
| D-22 | 2026-08-13 | `DJANGO_API_URL` read at runtime from `process.env` (drop build-time `env` bake in `next.config.ts`) | BFF route handlers are server-side; runtime env lets Docker/Railway override the backend URL without a rebuild | Active |
| D-23 | 2026-08-13 | Frontend containerized: `output: 'standalone'` + `frontend/Dockerfile` + `frontend` compose service (`DJANGO_API_URL=http://web:8000`) | Complements the existing backend Docker/compose setup (D-01); standalone output gives a small, runnable image; one `docker-compose up --build` boots db + web + frontend | Active |
| D-24 | 2026-08-13 | Runtime DB switched from MySQL to PostgreSQL: `django.db.backends.postgresql`, `psycopg2-binary`, compose `postgres:16`, `DB_PORT=5432` | User requirement; Postgres is the production target. SQLite stays for in-memory pytest only (`USE_SQLITE=1`) | Active |
| D-25 | 2026-08-13 | DB schema healthcheck: `website/checks.py` system check + `python manage.py healthcheck` command + compose `web` healthcheck and preflight gate | Detect-and-fail guarantees the API never serves traffic on a broken schema; `migrate` stays the auto-creator. System-check severity is selective: unapplied migrations stay Warning (Django runs system checks before applying migrations, so Error would deadlock first-run `migrate` on a fresh DB), while missing tables with no unapplied migrations and unverifiable schemas are Error (level raised from the original flat Warning, 2026-08-14, H5). The hard fail-fast gate is the `healthcheck` command exit code + compose. On Django 6.1 the check must be imported explicitly via `website/apps.py` `ready()` (app `checks.py` is no longer auto-loaded) and registered untagged (`@checks.register`), because `runserver` skips `Tags.database`-tagged checks when no DB alias is passed | Active |
| D-28 | 2026-08-14 | Preflight (`migrate && healthcheck`) moved from the compose `web` `command` chain into a Docker `ENTRYPOINT` script; compose `command` is plain gunicorn; `web` healthcheck slimmed (interval 10s, retries 6, no start_period) | The old `sh -c "migrate && healthcheck && gunicorn"` command raced the container healthcheck (which runs `manage.py healthcheck` in parallel and could report healthy before gunicorn bound). An entrypoint decouples the one-time preflight from the long-running command so the probe reflects real readiness; `depends_on: service_healthy` stays correct | Active |

| D-29 | 2026-08-14 | BFF proxy normalizes the forwarded path to always end with `/` (append when missing) before calling Django | Next's default `trailingSlash` behavior (308) strips the trailing slash before it reaches the route handler, so D-21's `nextUrl.pathname` never saw the slash; Django's `APPEND_SLASH` then 301s the no-slash path back to `/api/records/`, and with `redirect: 'manual'` (D-27) the browser follows → 308 → 301 → infinite loop, UI empty. Every DRF endpoint requires a trailing slash, so appending it in the proxy eliminates Django's 301 at the source and breaks the loop | Active |

| D-30 | 2026-08-14 | Frontend records list always opts into `?page=` (including `page=1`) so the client always receives the paginated `{count, next, previous, results}` shape | D-07 keeps backend pagination opt-in, so without `?page=` Django returns a plain array; `buildUrl` only sent `page` when `page > 1`, so page 1 returned an array and `data.results.map(...)` threw, blanking `/records`. Always sending `page` guarantees a stable shape for the pagination UI and delete-recount logic while leaving D-07's plain-array backend tests untouched | Active |
| D-31 | 2026-08-15 | Anonymous requests to token-gated endpoints return **401 NotAuthenticated** (not 403) | Five copy-pasted `permission_denied` overrides in `api/views.py` forced 403 for anonymous users, overriding DRF's correct 401-vs-403 semantics. Deleted all five; tests (`test_records.py:107,254`, `test_stats.py:15`, `test_auth.py:88`, `test_reports.py:15`) updated `403 → 401`. Authenticated-but-forbidden still 403 (DRF default) | Active |
| D-32 | 2026-08-15 | `RegisterSerializer.create()` returns a plain dict; `id` and `token` declared as read-only serializer fields | Removes the `(user, token)` tuple + `to_representation` override hack. DRF's `Serializer.to_representation` only serializes *declared* fields, so `id`/`token` must be read-only fields for the response to keep `{id, username, email, token}` — the BFF register route reads `data.token` to set the cookie | Active |
| D-33 | 2026-08-15 | Keep backend pagination opt-in (`?page=`) — M3 declined | Frontend already always sends `?page=1` (D-30/H8) and receives the paginated shape, while `recent-records.tsx` fetches *without* `?page=` and depends on the plain-array contract (D-07). Always-paginating the backend would break `recent-records.tsx` + 2 backend tests for zero UI gain | Active |
| D-34 | 2026-08-15 | New feature: **AI Lead Scoring** — score leads 1–10 + a one-sentence reason via Moonshot through AWS Lambda | User request; adds a recruiter-visible differentiator on top of the completed dashboard feature | Active |
| D-35 | 2026-08-15 | Remove the legacy website UI: delete `website/templates/`, the function-based views + `website/urls.py`, drop the `path('', include('website.urls'))` mount from `dcrm/urls.py`, and delete `mydb.py` | D-03 kept the legacy UI "for now"; the Next.js frontend now covers everything it did, so it is pure cruft. The `website` app itself stays — it hosts the `Record` model, `admin.py`, `checks.py`, and the healthcheck command | Active — supersedes D-03 |
| D-36 | 2026-08-15 | `Record` model + migration changes now allowed for this feature (adds `description`, `ai_score`, `ai_reason`, `ai_scored_at`, `scoring_status`, `updated_at`) | The "no model/migration changes — API is additive only" rule applied to the dashboard feature round only; lead scoring needs persisted fields | Active |
| D-37 | 2026-08-15 | Add `updated_at = DateTimeField(auto_now=True)` to `Record` | The re-score check needs a "record edited since last score" signal, and the model has no such timestamp today | Active |
| D-38 | 2026-08-15 | `ai_score`, `ai_reason`, `ai_scored_at`, `scoring_status` are read-only in `RecordSerializer`; `description` is read/write | Only the Lambda callback (secret-gated) may write score state; the client must never be able to forge a score | Active |
| D-39 | 2026-08-15 | Concurrency + re-score guard on `score-trigger`: `scoring_status == 'PROCESSING'` → **409**; `ai_scored_at` set and `updated_at <= ai_scored_at` → **400** "No changes detected" | Locking via a status field needs no extra infra; the timestamp check prevents wasted LLM calls on records that were not edited since the last score | Active |
| D-40 | 2026-08-15 | Fire-and-forget trigger via `threading.Thread` in `api/lambda_trigger.py` (no Celery / task queue) | Matches the PRD v1.0 design; one-off manual scoring does not justify a queue, and the endpoint returns 202 immediately | Active |
| D-41 | 2026-08-15 | Lambda Function URL auth NONE; the `PATCH /api/records/<pk>/score/` callback is gated by a shared `LAMBDA_SECRET` header | Function URLs have no easy IAM for off-platform callers; a shared secret is sufficient for a single internal callback endpoint | Active |
| D-42 | 2026-08-15 | Frontend polls the record detail every 3s up to 60s; on timeout shows an error + Retry that calls `reset-scoring` then re-enables the Score button | Bounded polling keeps load trivial; reset un-sticks the lock after a dead/failed Lambda | Active |
| D-43 | 2026-08-17 | The Lambda callback aligns `ai_scored_at = updated_at` via `Record.objects.filter(pk=...).update(ai_scored_at=record.updated_at)` (a `QuerySet.update` bypasses `auto_now`) | `updated_at` is `auto_now`, so merely saving the score bumps `updated_at` to a *later* time than `ai_scored_at`; the plan's guard `updated_at <= ai_scored_at → 400` would then never fire and re-scoring an unchanged record would waste an LLM call. Aligning makes the guard exact — it fires until a real client edit advances `updated_at` | Active |
| D-44 | 2026-08-17 | The score callback validates `ai_score` as an integer 1–10, else **400** | Rejects bad/missing payloads so the badge and reason UI never render out-of-range data; trusted-Lambda shortcut rejected as too risky for a recruiter-facing feature | Active |
| D-45 | 2026-08-17 | `api/lambda_trigger.py` uses stdlib `urllib.request` (no new dependency) and no-ops with a warning when `LAMBDA_FUNCTION_URL` is unset | Matches the repo's minimal-dependency convention (no `requests` in `requirements.txt`); the no-op keeps dev/pytest environments safe — no fire-and-forget thread ever hits the network when the Lambda isn't configured | Active |

> Note: D-25's preflight gate mechanism is now the entrypoint (D-28); the schema-check severity detail lives in D-25's `Why`. D-21's slash-preservation intent is realized by D-29 (normalize-forward), which also survives Next's URL normalization.
